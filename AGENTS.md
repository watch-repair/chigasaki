# Project Instructions for Kimi Code

## Project Overview

This is **Kawabata's Vintage Quartz Watch Repair** website — a static corporate site for a vintage quartz watch repair shop in Chigasaki, Japan. The site is bilingual (English/Japanese) and targets both local customers and international visitors.

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Framework | Astro v6 (Static Site Generation) |
| Hosting | Cloudflare Pages |
| Styling | Custom CSS (NO Tailwind CSS) |
| Content | Astro Content Collections (Markdown) |
| CI/CD | GitHub Actions |

## Directory Structure

```
chigasaki/
├── src/
│   ├── layouts/BaseLayout.astro      # Shared head, header, footer
│   ├── components/                   # Reusable Astro components
│   ├── content.config.ts             # Content Collections schema
│   ├── content/
│   │   ├── movements/                # Watch movement makers (Markdown)
│   │   └── parts/                    # Watch parts (Markdown)
│   └── pages/
│       ├── index.astro               # Top page
│       ├── movements/[slug].astro    # Dynamic movement detail
│       ├── movements/index.astro     # Movement list
│       ├── parts/[slug].astro        # Dynamic part detail
│       └── parts/index.astro         # Part list
├── public/                           # Static assets (CSS, JS, images)
└── .github/workflows/deploy.yml      # Auto-deploy to Cloudflare Pages
```

## Coding Conventions

### Astro Components
- Use `.astro` extension for all components
- Props interface must be explicitly typed with `export interface Props`
- Use `Astro.site` for absolute URL generation
- Static output only (`output: 'static'` in `astro.config.mjs`)

### Content Collections
- Schema defined in `src/content.config.ts` using Zod
- Content is Markdown with YAML frontmatter
- Use `getCollection()` for listing, access `.id` (not `.slug`) for paths
- Rendered HTML is available via `entry.rendered?.html`

### CSS
- **DO NOT introduce Tailwind CSS**. Maintain existing custom CSS files in `public/css/`.
- Existing CSS structure: `reset.css`, `variables.css`, `base.css`, `layout.css`, `components.css`
- Use CSS custom properties (`var(--*)`) defined in `variables.css`

### Bilingual Support
- Primary language: English
- Japanese text is wrapped in `<span lang="ja">` or `lang="ja"` attributes
- Keep Japanese translations parallel to English content

## Deployment

### Manual Deploy
```bash
npm run build
npm run deploy   # wrangler pages deploy
```

### Auto Deploy
Pushing to `main` branch triggers GitHub Actions workflow (`.github/workflows/deploy.yml`).

Required GitHub Secrets:
- `CLOUDFLARE_API_TOKEN`
- `CLOUDFLARE_ACCOUNT_ID`

## Adding New Content

### Adding a Movement Maker
1. Create `src/content/movements/<slug>.md`
2. Follow frontmatter schema: `title`, `description`, `category`, `country`, `founded`
3. Build and deploy

### Adding a Watch Part
1. Create `src/content/parts/<slug>.md`
2. Follow frontmatter schema: `title`, `description`, `category`
3. Build and deploy

No routing or component changes are needed for new Markdown content.

## SEO Requirements

- Every page must include structured data (JSON-LD) via `BaseLayout`
- BreadcrumbList schema on all pages
- Article schema on detail pages
- Sitemap auto-generated by `@astrojs/sitemap`
- `robots.txt` points to `sitemap-index.xml`

## Restrictions

- Do NOT add server-side logic (this is static SSG)
- Do NOT introduce React/Vue/Svelte components unless absolutely necessary
- Do NOT change existing CSS architecture without explicit approval
- Keep Japanese translations accurate and culturally appropriate
